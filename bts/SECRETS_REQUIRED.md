# Secrets required by the Valamm AI integration

No secret value is written in this folder. This lists what exists, where it lives, and how to get or set it without
exposing it.

## Summary

| Secret | Needed for | Local development | Cloud (DEV / UAT / PROD) |
|---|---|---|---|
| Google credentials (ADC) | Gateway → Vertex AI | Your own Google login (ADC file) | The Cloud Run service account; no key file |
| `INTERNAL_TOKEN` | Calling service → Gateway | Not needed (`AUTH_MODE=off`) | Secret Manager: `valamm-service-token` / `valamm-uat-internal-token` / `valamm-prod-internal-token` |
| Google API key | Not used | Do not create one | Do not create one |
| `AI_ANTHROPIC_API_KEY`, `AI_GROQ_API_KEY`, AWS keys | Other providers only | Not needed for Gemini | Not set |

## 1. Google credentials for Vertex AI (Application Default Credentials)

The Gemini provider (`services/ai/api/app/providers/gemini.py`) builds
`genai.Client(vertexai=True, project=…, location=…)` and lets the SDK find credentials. The code says there is no API
key "per org policy". Do not add a key or a downloaded service-account JSON key.

### Local development
1. Install the Google Cloud CLI and sign in with a Google account that has access to project
   `project-8ce5ae3e-81f4-4585-b74`:
   ```
   gcloud auth application-default login
   ```
2. This writes the ADC file (contains `client_id`, `client_secret`, `refresh_token`; `type: authorized_user`):
   - Windows: `%APPDATA%\gcloud\application_default_credentials.json`
   - macOS / Linux: `~/.config/gcloud/application_default_credentials.json`
3. The account needs the role **Vertex AI User** (`roles/aiplatform.user`) on the project, and the project must have
   `aiplatform.googleapis.com` enabled (both are already set for the DEV project through Terraform).
4. Restart the gateway after logging in.

Keep the ADC file private: never commit it, copy it into a project, or paste it anywhere. If it is exposed:
```
gcloud auth application-default revoke
gcloud auth application-default login
```

### Cloud Run
No secret to manage. The gateway runs as the environment's service account, which has `roles/aiplatform.user`:

| Environment | Service account (Terraform key) |
|---|---|
| DEV | `valamm-app-runtime` |
| UAT | `valamm-uat-run` |
| PROD | `valamm-prod-run` |

## 2. `INTERNAL_TOKEN` (service-to-service token)

- Checked by the gateway (`valamm_core.auth`, `internal_only=True`) when `AUTH_MODE=identity_platform`. Every caller
  must send `X-Valamm-Internal: <INTERNAL_TOKEN>`; `valamm_core.auth.install()` adds it automatically to requests for
  URLs in `INTERNAL_URLS`.
- Locally `AUTH_MODE` is `off`, so the token is not needed.
- In the cloud it is **generated by Terraform** (Secret Manager, `source = "generate"`, `random_length = 48`) and
  injected into every non-web Cloud Run service as the environment variable `INTERNAL_TOKEN` (`common_secrets`):

| Environment | Secret Manager secret id | Readable by |
|---|---|---|
| DEV | `valamm-service-token` | `valamm-app-runtime` |
| UAT | `valamm-uat-internal-token` | the UAT runtime account |
| PROD | `valamm-prod-internal-token` | the PROD runtime account |

The values in `infra/terraform/*/cloud_run_services/terraform.tfvars` (`INTERNAL_TOKEN = "valamm-service-token"`) are
**secret ids, not token values**.

### Giving another Cloud Run service the token
Add the service to the same `cloud_run_services` map (it then receives `common_secrets`), or reference the secret id
the same way. Grant its service account `roles/secretmanager.secretAccessor` on that secret if it is a different
account. Do not copy the value into a tfvars file, an `.env` in git, or a command line.

### Reading the value (only if a non-Terraform setup really needs it)
Pipe it straight into the place that needs it, never print it:
```
gcloud secrets versions access latest --secret=valamm-service-token --project=project-8ce5ae3e-81f4-4585-b74 \
  | <command that stores it, e.g. your platform's secret store>
```
You need `roles/secretmanager.secretAccessor` on that secret.

### Rotating
Terraform owns the value (`source = "generate"`). Rotating means a new secret version and a redeploy of every service
that reads it, because the gateway and all callers must hold the same value.

## 3. Not required
- **Google API key:** not used by the code.
- **`AI_ANTHROPIC_API_KEY`, `AI_GROQ_API_KEY`, AWS credentials:** only for `AI_PROVIDER=anthropic`, `groq` or
  `bedrock`. Empty in this repository.
- **Identity Platform / session cookie:** end-user sign-in. The gateway refuses end users anyway (`internal_only`).
